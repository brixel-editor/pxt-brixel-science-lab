# BRIXEL Science Lab — 0.6.0 개발판

초등 디지털 과학실험을 위한 **micro:bit V2** MakeCode 확장입니다. 마빗 실드 V2와 현행 DSL 마빗 보드의 센서를 읽고 LCD·OLED·네오픽셀로 표시하거나 바우어버드 프로에 USB·BLE로 보냅니다.

## MakeCode에 추가하기

[MakeCode micro:bit](https://makecode.microbit.org/)에서 프로젝트를 열고 **확장** 검색창에 다음 주소를 붙여 넣습니다.

```text
https://github.com/brixel-editor/pxt-brixel-science-lab
```

현재 공개 버전은 `v0.6.0`입니다. 링크로 가져오는 확장이며 MakeCode의 일반 검색 목록 승인을 받은 것은 아닙니다.

설치할 때 `radio`와 호환되지 않는다는 안내가 나오면 **radio를 제거하고 brixel-science-lab을 추가**합니다. 이 확장은 BLE 통신을 사용합니다.

`v0.3.1`부터 센서 소제목을 **센서명(칩셋·모델명)**으로 통일했습니다. 예: `eCO2(SGP30)`, `CO2(MH-Z19D)`, `기압(BMP280)`. 모델이 확인되지 않은 범용 모듈에는 모델명을 붙이지 않습니다. eCO2는 CO2 환산값이며 SGP30·CCS811 블록의 선택 메뉴에서 TVOC도 읽을 수 있습니다.

생체 신호의 센서명은 **심박 센서(MAX30102)**입니다. `v0.3.5`에서 사용자가 확인한 보유 센서 칩셋에 맞춰 정정했습니다. 메이크코드가 단일 그룹 소제목을 숨기므로 블록 문구에도 같은 이름을 표시합니다. 빨간빛·적외선 맥파 원시값을 읽으며 실물 검증은 아직 하지 않았습니다.

전기 측정과 바우어버드로 보내기는 **각각 6개 블록을 기본 카테고리에 모두 표시**하며 별도의 더 보기 메뉴를 두지 않습니다. 전압의 원시값·보정·전압(V), USB·블루투스 여러 값 전송도 바로 선택할 수 있습니다.

`v0.5.1`부터 **탁도·전압 센서는 마이크로비트 아날로그 핀으로 읽습니다.** 외장 ADS1115 주소·채널 블록과 드라이버를 제거했습니다. 두 센서 모두 보정 없이 읽는 원시값(0~1023) 블록이 있고, 필요할 때 기준값으로 보정해 투과율(%)·전압(V)을 사용할 수 있습니다.

### 기존 프로젝트 업데이트

`v0.6.0`에서 **RTC 시간 설정과 센서 보정 블록 15개**를 추가했습니다. NTC·TDS·토양 수분·무게·가속도·거리·고도 기준·공기질 온습도 보상을 제공합니다. 기존 pH는 7→4 또는 7→10 보정을 지원하며, TDS는 표준용액 보정 전에는 -1을 반환합니다. 보정 방법과 값의 의미는 아래 [보정·단위·값 해석 단원](#센서별-보정단위값-해석)에 정리했습니다.

**`RTC 시계 (12)시 (0)분 (0)초로 설정`**은 온도와 날씨 → 시계(DS1307)에 있습니다. 시는 0~23, 분·초는 0~59입니다. 시간을 맞출 때 한 번 실행하며 무한반복 안에 넣지 않습니다. [시계 예제](examples/clock-usb.ts)는 A 버튼으로 시간을 설정하고 초를 USB로 보냅니다.

`v0.5.2`에서 지문 등록을 **`지문 번호 (1)로 [1차 등록 / 2차 등록]` 실행 블록**으로 바꿨습니다. 1차 등록 후 손가락을 떼었다가 다시 대고 2차 등록하면 센서에 저장됩니다. 각 실행 직후 `지문 상태 코드`가 0이면 성공입니다.

프로젝트마다 설치한 확장 버전이 저장됩니다. GitHub에 새 버전을 게시해도 이미 열린 프로젝트는 이전 버전을 사용할 수 있습니다.

1. 메이크코드 편집기를 새로고침합니다.
2. **JavaScript → 탐색기**를 열고 `brixel-science-lab` 옆의 **버전/새로고침 버튼**을 누릅니다.
3. 버전이 `v0.6.0`인지 확인하고 **블록** 화면으로 돌아갑니다. 온도와 날씨의 `시계(DS1307)`에서 시간 설정 블록을, 각 센서 소제목 아래에서 보정 블록을 확인합니다.

확장 검색창에 붙이는 URL의 `#v0.6.0`만으로 설치 버전이 고정되지는 않을 수 있습니다. 계속 이전 버전이라면 **탐색기 → pxt.json → Edit settings as text**에서 `dependencies` 안의 해당 항목만 다음 값으로 바꾸고 다른 파일로 이동해 저장한 뒤 편집기를 새로고침합니다.

```json
"brixel-science-lab": "github:brixel-editor/pxt-brixel-science-lab#v0.6.0"
```

기존 프로젝트의 다른 설정과 코드는 그대로 둡니다.

**이전 참·거짓 지문 등록 블록을 사용한 프로젝트:** 조건 칸에 넣었던 등록 블록은 실행 순서에 놓는 새 블록으로 교체합니다. 성공 여부를 판단하려면 등록 다음에 `지문 상태 코드 = 0` 조건을 사용합니다. TypeScript의 `enrollFingerprint(step, id)`도 이제 값을 반환하지 않습니다.

**이전 ADS1115 블록을 사용한 프로젝트:** 업데이트 전에 기존 외장 ADC 주소·탁도·전압 블록을 제거하고, 업데이트 후 새 아날로그 핀 블록을 놓아 실제 P핀을 선택합니다. A0~A3은 P0~P3과 다르므로 자동 변환하지 않습니다. TypeScript에서는 주소 설정 호출을 삭제하고 `ScienceADCChannel.A0` 등을 실제 연결의 `ScienceAnalogPin.P1` 등으로 바꿉니다. 기존 보정값은 재사용하지 않습니다.

현재 **10개 카테고리, 100개 블록**을 구현했습니다. V2 컴파일과 소프트웨어 검증을 마쳤으며, 실물 센서·보드·무선 연결 검증 전입니다. **실물 정확도는 아직 보장하지 않습니다.** 센서별 값의 의미와 실물 검증 항목은 아래에 구분합니다.

## 시작 예제

실드 소켓의 **실제 P핀 번호**를 선택합니다. 커넥터 열 번호와 P핀 번호는 다를 수 있습니다. 모듈 전원·신호 전압을 확인합니다. 아날로그 입력은 3.3V 범위이며 P3/P4/P10을 쓰면 LED 화면이 꺼집니다.

조도 센서 P1 → USB, 0.2초마다 전송:

```typescript
basic.forever(function () {
    scienceData.sendValueUSB(scienceLight.light(ScienceAnalogPin.P1))
    basic.pause(200)
})
```

수온 센서 P8 → BLE:

```typescript
scienceData.startBluetooth()
basic.forever(function () {
    if (scienceData.bluetoothConnected()) {
        let water = scienceWater.temperature(ScienceDigitalPin.P8, 1)
        if (water != -127) scienceData.sendValueBluetooth(water)
    }
    basic.pause(1000)
})
```

바우어버드는 **구분자 쉼표**, USB는 **115200 baud**, BLE는 **micro:bit 모드**로 연결하고 기록을 시작합니다. 여러 센서는 여러 값 전송 블록의 배열에 일정한 순서로 넣습니다. 예: `scienceData.sendUSB([temperature, humidity, light])`.

한 측정은 `23.5,48,700\n` 형태입니다. 센서명·단위·진단 문구는 데이터 줄에 넣지 않습니다. 전송 블록은 반환값 없는 명령형입니다. TypeScript의 `trySendUSB`/`trySendBluetooth`는 전송 시도 여부를 반환하며 웹앱 도착 확인을 뜻하지 않습니다. 빈 배열·NaN·Infinity·연결 전 BLE 전송은 건너뜁니다.

## 값의 의미와 조건

- 단순 아날로그 센서는 0~1023 원시값입니다. lux·dB·N·UV 지수로 임의 변환하지 않습니다. 센서가 빠진 상태는 확실히 판별할 수 없습니다.
- 단순 디지털 센서는 전기 신호 0/1입니다. pH·PT100·전류 보정은 프로그램을 다시 시작하면 사라집니다.
- 온도 실패는 -127, PT100/전류/GPS는 -9999, MPU6050은 -999, 습도·거리·기압·공기질·지문 인식 등은 -1입니다. 바우어버드는 이 숫자도 표시하므로 예제처럼 해당 센서의 실패값을 검사할 수 있습니다.
- SGP30은 처음 약 15초, CCS811은 20분 동안 -1입니다. eCO₂는 환산값입니다. **MH-Z19D 블록은 직접 측정한 CO₂**이며 시작 후 60초 동안 -1입니다.
- OLED 기본은 SSD1306입니다. 실제 칩이 SH1106인 경우만 바꿉니다. 화면 크기로 칩을 단정하지 않습니다. LCD·OLED 텍스트는 영어·숫자만 지원합니다.
- 사용자가 확정한 초음파 핀 순서는 **G–V–ECHO–TRIG**입니다. 예를 들어 DSL의 G/V/P13/P14 단자라면 에코=P13, 트리거=P14를 선택합니다. 5V ECHO 신호는 전압 변환이 필요합니다.
- PMS·MH-Z19D·GPS·AS608은 V2 센서용 UART 하나를 공유합니다. **마지막에 시작한 센서 하나만 읽으며 다른 센서는 실패값**을 반환합니다(GPS -9999, 나머지 -1). USB115200 송신은 별도 UART에서 유지합니다. RX/TX는 micro:bit 기준이며 센서 TX→RX, 센서 RX→TX입니다. UART 센서 시작 블록은 시작할 때 한 번 실행합니다. GPS/AS608의 통신 속도 메뉴는 모듈 설정을 변경하지 않고 micro:bit의 속도를 맞춥니다.
- PMS는 전원 공급 후 기본 자동 송신 모드를 사용합니다. 처음 30초, 체크섬 오류, 3초 이상 수신 없음은 -1입니다. 모듈을 수동 모드로 바꿨다면 전원을 다시 켜 기본 자동 모드로 돌아온 뒤 사용합니다.
- GPS는 보유 D_031/D_032 모듈·안테나의 NMEA RMC/GGA 출력용입니다. 칩셋명은 확정하지 않았습니다. 위도·경도(소수점 도), 고도(m), 속도(km/h), 위성 수를 읽습니다. 기본 속도 9600, 각 항목은 3초 이상 갱신되지 않으면 -9999입니다. 위치 확인은 실외에서 먼저 시험합니다.
- 지문 AS608은 기본 비밀번호 0·주소 FFFFFFFF·통상 57600 baud 조건입니다. 같은 손가락을 **1차 등록 → 손가락 떼고 다시 대기 → 같은 번호로 2차 등록** 순서로 등록합니다(60초 이내). 2차 등록까지 성공하면 센서에 저장됩니다. 번호는 1부터 센서 저장 용량 미만이며 같은 번호는 덮어씁니다. 실행 직후 지문 상태 코드로 결과를 확인합니다. 인식 블록은 등록 번호를 반환하고 이미지·지문 특징 데이터는 송신하지 않습니다. 상태 0=성공, 2=손가락 없음, 9=일치 없음, 10=두 지문 불일치, -1=설정·통신·입력 오류입니다. 통신 오류 후 시작 블록을 다시 실행합니다.
- A_016/017/018 아날로그 먼지 세트는 **센서 5V 전원·VO 분압·전압에 맞는 LED 구동 회로**를 전제로 합니다. Sharp GP2Y1010 계열의 280µs 샘플/320µs LED 펄스 조건으로 직접 ADC를 읽고 8회 평균 원시값 0~1023을 반환합니다. 소제목에는 미확정 모델명을 붙이지 않습니다. PM2.5·µg/m³ 환산은 하지 않습니다. 마이크 등 ADC 스트리밍과 동시 사용하거나 펄스 타이밍을 놓치면 -1입니다. 실물 회로와 파형 검증은 남아 있습니다.
- MQ 가스 9종은 사용자 결정에 따라 MakeCode 기본 **핀 → 아날로그 값 읽기** 블록을 사용합니다. 모듈 출력이 micro:bit 입력 범위를 넘지 않도록 연결하며 원시값을 가스 농도 ppm으로 표시하지 않습니다.
- 탁도·전압은 **선택한 마이크로비트 아날로그 핀의 0~1023 원시값**을 읽습니다. 원시값 블록은 보정이 필요 없습니다. 센서 모듈의 출력 신호는 0~3.3V이면서 보드 전원 이하여야 합니다. 모듈 전원 전압과 출력 신호 전압을 구분합니다.
- 탁도 보정은 맑은 물의 원시값을 100%로 저장합니다. 작아질수록 흐린 물이며 NTU가 아닙니다. 전압은 분압 모듈을 통해 기준 계기로 확인한 직류 전압을 보정하고 같은 핀의 원시값에서 V를 계산합니다. 모듈의 25V 표기가 마이크로비트의 측정 한도를 뜻하지 않으며 실제 한도는 분압비와 핀 입력 전압에 따라 달라집니다. 측정 전압을 마이크로비트 핀에 직접 연결하지 않습니다.
- 두 센서의 보정은 핀별로 저장되고 재시작하면 사라집니다. 보정 기준 원시값은 5~1022여야 합니다. 잘못된 재보정은 해당 핀의 이전 보정을 지웁니다. 보정 전·입력 포화(1023)는 보정값 블록에서 -1을 반환하며 원시값 블록에서는 1023을 그대로 볼 수 있습니다. 아날로그 센서 미연결은 확실히 식별할 수 없습니다.
- MAX30102는 20~100ms마다 읽는 광학 원시값이며 심박수·SpO₂가 아닙니다. EC11은 손으로 천천히 돌리는 신호 주기 수이며 빠른 회전은 놓칠 수 있습니다. APDS9960 방향은 0 없음/1 위/2 아래/3 왼쪽/4 오른쪽이고 한 번 읽으면 지워집니다.
- DS1307은 `RTC 시계 (12)시 (0)분 (0)초로 설정`으로 시간을 맞추고 작동시킵니다. 24시간제이며 정지 비트(CH)도 해제합니다. 설정은 시간을 맞출 때 한 번 실행하세요. 무한반복에 넣으면 계속 같은 시각으로 돌아가고, 시작하면에 넣으면 보드를 재시작할 때마다 다시 맞춰집니다. 읽기 블록은 시·분·초를 반환하며 정지·잘못된 시계 값·읽기 오류는 -1입니다. 유효한 기존 날짜는 유지하고 잘못된 날짜만 2000-01-01로 초기화합니다(날짜를 현재 날짜로 맞추는 기능은 아님). TypeScript의 `trySetClock(hour, minute, second)`는 입력/I2C 오류 시 false를 반환합니다. 설정 실패 시 배선을 확인하고 다시 설정하세요. [DS1307 데이터시트](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1307.pdf)의 시간 레지스터 규칙을 따릅니다.
- MPU6050/DS1307(0x68), TCS34725/VL53L0X(0x29), MLX90614/CCS811(0x5A)은 같은 주소끼리 직접 병렬 연결하지 않습니다.

## 센서별 보정·단위·값 해석

### 1. 원시값과 실제 물리량

마이크로비트 아날로그 입력의 반환 범위는 **0~1023, 총 1024단계**입니다. `1024`가 최댓값은 아닙니다. 이 숫자는 센서 출력 전압의 크기를 나타내는 ADC 코드이며 그 자체가 온도·조도·소음·무게는 아닙니다. 단순 아날로그 블록의 문구도 `원시값`으로 명확히 했습니다. 이전 버전의 `측정값`과 같은 값입니다. 입력 범위와 API는 [MakeCode analogReadPin](https://makecode.microbit.org/reference/pins/analog-read-pin)을 참고합니다.

`r`=원시값, `r0`=영점 원시값, `r1/r2`=기준점에서 읽은 원시값, `x1/x2`=기준 계기로 확인한 물리량으로 씁니다.

| 목적 | 식 | 적용 조건 |
|---|---|---|
| 핀 전압의 대략적 환산 | `Vpin ≈ r × VFS / 1023` | 이 프로젝트의 아날로그 환산은 VFS=3.3V를 가정. 전원·ADC 오차가 있으므로 정확한 V는 기준 전압 보정 사용 |
| 영점에서의 변화 | `Δr = r - r0` | 단위는 여전히 ADC 코드. 음수가 나올 수 있으며 물리 단위를 붙이지 않음 |
| 두 점 선형 환산 | `x = x1 + (r-r1) × (x2-x1)/(r2-r1)` | `r1≠r2`, 해당 구간에서 선형이라는 근거 필요. 두 기준 사이에서 사용하고 제3의 값으로 검증 |
| 상대 척도 | `q = 100 × (r-r0)/(r100-r0)` | 사용자 정의 0~100 척도. 실제 수분 함량·반사율 등을 자동으로 뜻하지 않음 |
| 임계값 감지 | `r`과 두 상태 중간의 기준값 비교 | 움직임·빛·물의 유무 판단. 채터링 방지를 위해 켜짐/꺼짐 기준을 조금 다르게 설정할 수 있음 |

예를 들어 기준 전압 5V를 모듈에 넣었을 때 원시값이 400이라면 같은 배선에서 `입력 전압 = r × 5 / 400`입니다. **5V를 마이크로비트 핀에 직접 넣는다는 뜻이 아닙니다.** 분압 모듈을 거친 핀의 신호가 입력 한도 이하여야 합니다. 실제 입력 한도는 분압비·전원·배선으로 결정됩니다.

센서가 빠져도 아날로그 핀이 임의의 숫자를 읽을 수 있습니다. 0이나 1023 하나만으로 연결 여부를 확정할 수 없습니다. 포화된 1023을 더 큰 물리량으로 환산하지 마세요. -1/-127/-999/-9999 같은 실패값을 먼저 검사하고 나서 식을 적용합니다. `%` 표시는 같은 의미가 아닙니다: 상대습도, 토양 상대척도, 탁도 출력비를 구분하세요.

### 2. 공통 보정·정확도 확인 순서

1. 기준 계기/표준물질의 단위·유효기간·정확도, 센서 전원·배선·장착·예열 조건을 확인합니다. 온도나 물이 닿는 실험은 모듈의 실제 정격을 따릅니다.
2. 보정 블록은 기준물질이 안정된 상태에서 버튼 등으로 한 번 실행합니다. **보정 명령을 무한반복에 넣지 않습니다.** 공기질 온습도 보상은 환경 변화에 맞춰 주기적으로 갱신하는 예외입니다.
3. 영점과 기준점으로 보정하고, **보정에 쓰지 않은 중간값 및 다른 기준값**에서 각각 10회 이상 비교합니다. 저·중·고 3개 이상 조건에서 같은 방향/반대 방향으로 확인하면 비선형성과 이력 차이도 드러납니다.
4. 기준값, 원시값, 보정값, 평균, 최소·최대, 오차를 기록합니다. `오차=측정값-기준값`, `상대오차(%)=100×오차/기준값`이며 기준값이 0이면 상대오차를 쓰지 않습니다. 허용 오차는 실험 목적과 실제 모듈/기준 계기 사양으로 정합니다.
5. 센서·핀·전원·배선·장착·용액 온도를 바꾸면 다시 보정합니다. 이 확장의 소프트웨어 보정은 RAM에 있어 **재시작하면 사라집니다.** RTC 시간과 AS608 지문 저장은 센서 자체의 별도 상태입니다.

아날로그 기준점은 16회·약 80ms를 읽어 심한 흔들림(최댓값−최솟값>20코드)을 거절합니다. 이것은 짧은 안정성 검사이며, 용액 안정화나 센서 예열을 대신하지 않고 정확도를 보증하는 기준도 아닙니다. pH는 **7→4 또는 7→10**, PT100은 **첫 기준→둘째 기준**, 토양은 **마른 흙→젖은 흙** 순서입니다. 첫 기준을 다시 잡으면 이전 둘째 기준을 무효화합니다. 잘못된 재보정 뒤 실패값이 나오면 조건을 고쳐 다시 보정하세요.

### 3. 아날로그 센서별 준비물·변환·해석

|---|---|---|---|

| 자외선 (`uvRaw`) | 0~1023 | 기준 UV 계기, 정확한 센서 모델·파장 응답·증폭도. 출력 기울기가 확인된 선형 모듈만 `E=(V-Vdark)/감도` | UV 강도와 UV 지수는 다름. 정확한 감도·파장 가중치가 없으므로 현재 블록은 원시값 |

| PT100 (`pt100`) | °C | 기준 온도계, 실험 구간의 두 안정된 온도. 첫·둘째 기준 보정 후 중간 온도로 확인 | 두 점 선형식. 첫·둘째 온도 차이≥1°C, 원시값 차이≥5. 두 점 사이에서만 읽기. 모듈·프로브 실제 정격 우선 |

| 전압 (`voltageRaw`, `voltage`) | 원시값 / DC V | 멀티미터, 안전한 기준 전압, 분압 모듈. 기준 전압 보정 후 `V=r×Vref/rref` | 영점 0을 가정한 1점 비례식. 무전압 오프셋이 크면 배선·회로를 점검하고 2점 특성을 별도 검증. 핀 입력 한도 준수 |
| 아날로그 미세먼지 (`analogDust`) | 펄스 동기 ADC 0~1023 | 정확한 모델 자료, 정상 전원·분압, 깨끗한 공기, 기준 입자계, 가능하면 오실로스코프 | 깨끗한 공기 기준 `r-r0`는 변화량만 의미. 모델별 감도·기준 입자 없이 µg/m³·PM2.5로 환산하지 않음. 펄스/회로 검증도 필요 |
| MQ 가스 9종(기본 핀 블록) | 0~1023 | 정확한 MQ 모델, 히터·부하저항 회로, 충분한 예열, 해당 가스 표준 농도 | 알려진 단순 분압 회로일 때만 `Rs=RL(Vc/Vout-1)`; 기준 가스에서 R0를 구하고 해당 모델 `Rs/R0↔ppm` 곡선 사용. 모듈 분압·증폭을 먼저 역산. 서로 다른 MQ에 같은 식/깨끗한 공기 영점을 적용하지 않음 |

**TDS 계산 상세:** `V=r×3.3/1023`, `f(V)=133.42V³-255.86V²+857.39V`, `estimate=0.5f(V)/(1+0.02(T-25))`, `gain=기준용액ppm/estimate(보정 시)`, 최종 `ppm=gain×estimate`. 전압을 먼저 온도로 나누던 이전 방식을 전도도 환산 뒤 온도 보상하는 방식으로 바꿨습니다. 이 식은 [DFRobot Gravity TDS의 변환·보정 방식](https://github.com/DFRobot/GravityTDS/blob/master/GravityTDS.cpp)을 참고한 **호환 모듈 가정**이며 보유 모듈에서 표준용액 여러 점으로 검증해야 합니다. 0.5 계수의 1413µS/cm는 706.5ppm이고 제품 안내에서 약 707ppm으로 표기됩니다. 0.7 계수로 표시한 다른 TDS 계기와 그대로 비교하지 마세요.

### 5. 0/1 감지 센서와 출력 장치

아래 센서는 **전기 신호 0 또는 1**을 반환합니다. 거리·온도 등의 연속 물리량 보정이 아니라 감지 극성·임계값·장착 조건을 확인합니다. 모듈에 조절 나사가 있으면 기준 상황에서 조절하고 전후 상태를 기록합니다.

| 센서 | 준비물·확인 방법 | 값 해석 |
|---|---|---|
| 버튼 | 손으로 누르기/놓기 각 10회 | 눌렀을 때 0인지 1인지 확인, 접점 튐 확인 |
| 락커 스위치 | 두 위치를 번갈아 선택 | ON/OFF 위치의 신호 극성 확인 |
| 디지털 터치 | 손가락 접촉/비접촉 | 감지/유지 모드와 젖은 손의 영향 확인 |
| 인체 감지 | 사람의 정지·이동, 필요한 예열 | 보통 움직임 감지이며 거리나 사람 수가 아님 |
| 기울기 | 수평·기울인 기준 자세 | 특정 자세에서 접점 전환, 각도 °가 아님 |
| 디지털 진동 | 정지·가벼운 진동을 반복 | 임계값을 넘은 감지 신호, 가속도 g 아님 |
| 디지털 수위 | 실제 용기와 두 수위 | 설정 높이 통과 여부, 물의 양 L 아님 |
| 포토인터럽터 | 차광판·슬롯 통과 반복 | 막힘/열림. 속도에는 알려진 거리와 시간 측정이 추가로 필요 |
| 화염 감지 | 센서용 IR 시험 광원 등 통제된 시험 조건 | 광학 감지 신호, 화염 온도나 안전 인증 경보가 아님 |

LCD·OLED·네오픽셀은 출력 장치이므로 센서 보정 대상이 아닙니다. 숫자가 화면에 표시된다는 사실은 측정 정확도를 확인한 것이 아닙니다. USB/BLE 송신 역시 값의 정확성을 보정하지 않습니다.

## 검증과 소스

PXT microbit 9.1.1 / pxt-core 13.0.1에서 V2 네이티브 빌드, 100개 블록 정의와 한국어 인자, 센서 프로토콜 모의 시험, 실제 바우어버드 USB/BLE 수신 함수 검사를 통과했습니다. 실물 검증 범위와 순서는 [실물검증.md](실물검증.md)에 있습니다.
