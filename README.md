# BRIXEL Science Lab — 0.7.2 개발판

초등 디지털 과학실험을 위한 **micro:bit V2** MakeCode 확장입니다. 마빗 실드 V2와 현행 DSL 마빗 보드의 센서를 읽고 LCD·OLED·네오픽셀로 표시하거나 바우어버드 프로에 USB(유선)로 보냅니다. 블루투스 무선 전송은 짝 확장 [brixel-science-lab-ble](https://github.com/brixel-editor/pxt-brixel-science-lab-ble)을 추가할 때만 켜집니다.

## MakeCode에 추가하기

[MakeCode micro:bit](https://makecode.microbit.org/)에서 프로젝트를 열고 **확장** 검색창에 다음 주소를 붙여 넣습니다.

```text
https://github.com/brixel-editor/pxt-brixel-science-lab
```

현재 공개 버전은 `v0.7.2`입니다. 링크로 가져오는 확장이며 MakeCode의 일반 검색 목록 승인을 받은 것은 아닙니다.

`v0.7.0`부터 이 확장은 **블루투스를 쓰지 않습니다**(유선 USB 전송만). 그래서 `radio`와 함께 쓸 수 있습니다. **무선 실험을 할 때만** 블루투스 짝 확장을 추가합니다:

```text
https://github.com/brixel-editor/pxt-brixel-science-lab-ble
```

짝 확장을 추가할 때 `radio`와 호환되지 않는다는 안내가 나오면 radio를 제거합니다.

`v0.3.1`부터 센서 소제목을 **센서명(칩셋·모델명)**으로 통일했습니다. 예: `eCO2(SGP30)`, `CO2(MH-Z19D)`, `기압(BMP280)`. 모델이 확인되지 않은 범용 모듈에는 모델명을 붙이지 않습니다. eCO2는 CO2 환산값이며 SGP30·CCS811 블록의 선택 메뉴에서 TVOC도 읽을 수 있습니다.

생체 신호의 센서명은 **심박 센서(MAX30102)**입니다. `v0.3.5`에서 사용자가 확인한 보유 센서 칩셋에 맞춰 정정했습니다. 메이크코드가 단일 그룹 소제목을 숨기므로 블록 문구에도 같은 이름을 표시합니다. 빨간빛·적외선 맥파 원시값을 읽으며 실물 검증은 아직 하지 않았습니다.

전기 측정과 바우어버드로 보내기는 **각각 6개 블록을 기본 카테고리에 모두 표시**하며 별도의 더 보기 메뉴를 두지 않습니다. 전압의 원시값·보정·전압(V), USB 여러 값 전송도 바로 선택할 수 있습니다(블루투스 전송은 짝 확장).

`v0.5.1`부터 **탁도·전압 센서는 마이크로비트 아날로그 핀으로 읽습니다.** 외장 ADS1115 주소·채널 블록과 드라이버를 제거했습니다. 두 센서 모두 보정 없이 읽는 원시값(0~1023) 블록이 있고, 필요할 때 기준값으로 보정해 투과율(%)·전압(V)을 사용할 수 있습니다.

### 기존 프로젝트 업데이트

`v0.7.2`에서 **네오픽셀을 「설정 + LED 번호별 제어」로 바꿨습니다.**

```
시작하면:  네오픽셀 설정 핀 (P9) LED 개수 (8)
          네오픽셀 (1) 번 LED 밝기 (32) 색 [빨강 255 초록 0 파랑 0]
          네오픽셀 모든 LED 밝기 (32) 색 [ ]
          네오픽셀 모든 LED 끄기
```

LED 번호는 1번부터입니다. 번호에 변수를 넣으면 LED를 차례로 켤 수 있고, 밝기에 조도 센서 값 같은 변수를 넣을 수 있습니다. 예전 「핀·개수·밝기·색」 한 블록과 「네오픽셀 밝기」 블록은 저장된 작품이 열리도록 남겨 두었지만 블록 목록에서는 숨겼습니다.

`v0.7.1`에서 **미세먼지 시작 블록을 모델별로 나눴습니다**: 3핀 `미세먼지 센서 PMS3003 시작 핀 ( )`(신호선 1개), 4핀 `미세먼지 센서 PMS7003 시작 RX ( ) TX ( )`. 예전 작품의 시작 블록은 PMS7003 블록으로 그대로 열립니다(PMS3003 에서도 동작).

`v0.7.0`에서 **블루투스 전송 블록을 짝 확장 [brixel-science-lab-ble](https://github.com/brixel-editor/pxt-brixel-science-lab-ble)으로 옮겼습니다.** 과학실험의 기본은 USB 유선 전송이라, 블루투스를 쓰지 않는 수업에서는 블루투스가 아예 켜지지 않습니다(센서 읽기 실패가 줄고 메모리를 아낌, radio 와 함께 사용 가능). 예전 판의 블루투스 블록으로 만든 작품은 짝 확장을 추가하면 같은 블록이 다시 연결됩니다.

`v0.6.7`에서 **`네오픽셀 밝기 ( )` 블록**을 더했습니다(조도 센서 값 같은 변수로 마지막에 켠 네오픽셀의 밝기를 바꿈). **DHT11/22** 는 신호를 C++로 읽어 실패가 줄었고, 한 번 실패해도 직전 값을 유지합니다(3번 연속 실패해야 -127).

`v0.6.6`에서 네오픽셀 블록을 **두 줄**로 줄였습니다: 첫 줄 `네오픽셀 핀 (P9) 개수 (8) 밝기 (32)`, 둘째 줄 `색 [빨강 초록 파랑]`. 개수·밝기는 숫자를 직접 치거나 목록에서 고르는 칸이라 변수는 끼울 수 없습니다.

`v0.6.5`에서 네오픽셀 색 칸의 기본 블록을 **`빨강 (255) 초록 (0) 파랑 (0)`**으로 바꿨습니다. 숫자를 누르면 0~255 밀대가 나와 색을 직접 섞을 수 있습니다. 색 변수나 다른 색 값도 그 칸에 끼울 수 있습니다.

`v0.6.4`에서 **네오픽셀 블록에 색상표와 밝기(0~255)**를 넣었습니다: `네오픽셀 핀 (P9) 개수 (8) 색 (색상표) 밝기 (32)`. LED가 많고 밝으면 실드 5V 전류가 모자랄 수 있으니 낮은 밝기부터 시작합니다. 예전 색 고르기 블록은 저장된 작품이 열리도록 남겨 두었지만 블록 목록에서는 숨겼습니다.

`v0.6.3`에서 **초음파 측정 방식을 바꿨습니다.** 잠깐 값이 나오다가 -1만 나오던 문제 때문에, 메이크코드 기본 `pulseIn` 대신 아두이노처럼 에코 핀을 직접 확인하는 방식으로 잽니다.

`v0.6.2`에서 **LCD·OLED 표시 블록에 숫자 변수를 바로 끼울 수 있게** 했습니다(문자로 변환 블록 불필요, 소수는 둘째 자리 반올림). **초음파 블록은 에코 → 트리거 순서**(기본 에코 P13·트리거 P14)로 바꾸고, 반사가 없으면 최대 3번 다시 측정합니다.

`v0.6.1`은 README를 센서마다 독립된 소제목으로 나누고, 맨 위에 센서별 바로가기와 계산 예를 추가한 문서 업데이트입니다. 블록 기능은 v0.6.0과 같습니다.

`v0.6.0`에서 **RTC 시간 설정과 센서 보정 블록 15개**를 추가했습니다. NTC·TDS·토양 수분·무게·가속도·거리·고도 기준·공기질 온습도 보상을 제공합니다. 기존 pH는 7→4 또는 7→10 보정을 지원하며, TDS는 표준용액 보정 전에는 -1을 반환합니다. 보정 방법과 값의 의미는 아래 [보정·단위·값 해석 단원](#센서별-보정단위값-해석)에 정리했습니다.

**`RTC 시계 (12)시 (0)분 (0)초로 설정`**은 온도와 날씨 → 시계(DS1307)에 있습니다. 시는 0~23, 분·초는 0~59입니다. 시간을 맞출 때 한 번 실행하며 무한반복 안에 넣지 않습니다. [시계 예제](examples/clock-usb.ts)는 A 버튼으로 시간을 설정하고 초를 USB로 보냅니다.

`v0.5.2`에서 지문 등록을 **`지문 번호 (1)로 [1차 등록 / 2차 등록]` 실행 블록**으로 바꿨습니다. 1차 등록 후 손가락을 떼었다가 다시 대고 2차 등록하면 센서에 저장됩니다. 각 실행 직후 `지문 상태 코드`가 0이면 성공입니다.

프로젝트마다 설치한 확장 버전이 저장됩니다. GitHub에 새 버전을 게시해도 이미 열린 프로젝트는 이전 버전을 사용할 수 있습니다.

1. 메이크코드 편집기를 새로고침합니다.
2. **JavaScript → 탐색기**를 열고 `brixel-science-lab` 옆의 **버전/새로고침 버튼**을 누릅니다.
3. 버전이 `v0.7.2`인지 확인하고 **블록** 화면으로 돌아갑니다. 온도와 날씨의 `시계(DS1307)`에서 시간 설정 블록을, 각 센서 소제목 아래에서 보정 블록을 확인합니다.

확장 검색창에 붙이는 URL의 `#v0.7.2`만으로 설치 버전이 고정되지는 않을 수 있습니다. 계속 이전 버전이라면 **탐색기 → pxt.json → Edit settings as text**에서 `dependencies` 안의 해당 항목만 다음 값으로 바꾸고 다른 파일로 이동해 저장한 뒤 편집기를 새로고침합니다.

```json
"brixel-science-lab": "github:brixel-editor/pxt-brixel-science-lab#v0.7.2"
```

기존 프로젝트의 다른 설정과 코드는 그대로 둡니다.

**이전 참·거짓 지문 등록 블록을 사용한 프로젝트:** 조건 칸에 넣었던 등록 블록은 실행 순서에 놓는 새 블록으로 교체합니다. 성공 여부를 판단하려면 등록 다음에 `지문 상태 코드 = 0` 조건을 사용합니다. TypeScript의 `enrollFingerprint(step, id)`도 이제 값을 반환하지 않습니다.

**이전 ADS1115 블록을 사용한 프로젝트:** 업데이트 전에 기존 외장 ADC 주소·탁도·전압 블록을 제거하고, 업데이트 후 새 아날로그 핀 블록을 놓아 실제 P핀을 선택합니다. A0~A3은 P0~P3과 다르므로 자동 변환하지 않습니다. TypeScript에서는 주소 설정 호출을 삭제하고 `ScienceADCChannel.A0` 등을 실제 연결의 `ScienceAnalogPin.P1` 등으로 바꿉니다. 기존 보정값은 재사용하지 않습니다.

현재 **10개 카테고리, 100개 블록**을 구현했습니다. V2 컴파일과 소프트웨어 검증을 마쳤으며, 실물 센서·보드·무선 연결 검증 전입니다. **실물 정확도는 아직 보장하지 않습니다.** 센서별 값의 의미와 실물 검증 항목은 아래에 구분합니다.

## 시작 예제

실드 소켓의 **실제 P핀 번호**를 선택합니다. 커넥터 열 번호와 P핀 번호는 다를 수 있습니다. 모듈 전원·신호 전압을 확인합니다. 아날로그 입력은 3.3V 범위이며 P3/P4/P10을 쓰면 LED 화면이 꺼집니다.

조도 센서 P1 → USB, 0.2초마다 전송:

```typescript
basic.forever(function () {
    scienceData.sendValueUSB(scienceLight.light(ScienceAnalogPin.P1))
    basic.pause(200)
})
```

수온 센서 P8 → BLE (짝 확장 brixel-science-lab-ble 필요):

```typescript
scienceBluetooth.startBluetooth()
basic.forever(function () {
    if (scienceBluetooth.bluetoothConnected()) {
        let water = scienceWater.temperature(ScienceDigitalPin.P8, 1)
        if (water != -127) scienceBluetooth.sendValueBluetooth(water)
    }
    basic.pause(1000)
})
```

바우어버드는 **구분자 쉼표**, USB는 **115200 baud**, BLE는 **micro:bit 모드**로 연결하고 기록을 시작합니다. 여러 센서는 여러 값 전송 블록의 배열에 일정한 순서로 넣습니다. 예: `scienceData.sendUSB([temperature, humidity, light])`.

한 측정은 `23.5,48,700\n` 형태입니다. 센서명·단위·진단 문구는 데이터 줄에 넣지 않습니다. 전송 블록은 반환값 없는 명령형입니다. TypeScript의 `trySendUSB`(짝 확장은 `scienceBluetooth.trySend`)는 전송 시도 여부를 반환하며 웹앱 도착 확인을 뜻하지 않습니다. 빈 배열·NaN·Infinity·연결 전 BLE 전송은 건너뜁니다.

## 값의 의미와 조건

- 단순 아날로그 센서는 0~1023 원시값입니다. lux·dB·N·UV 지수로 임의 변환하지 않습니다. 센서가 빠진 상태는 확실히 판별할 수 없습니다.
- 단순 디지털 센서는 전기 신호 0/1입니다. pH·PT100·전류 보정은 프로그램을 다시 시작하면 사라집니다.
- 온도 실패는 -127, PT100/전류/GPS는 -9999, MPU6050은 -999, 습도·거리·기압·공기질·지문 인식 등은 -1입니다. 바우어버드는 이 숫자도 표시하므로 예제처럼 해당 센서의 실패값을 검사할 수 있습니다.
- SGP30은 처음 약 15초, CCS811은 20분 동안 -1입니다. eCO₂는 환산값입니다. **MH-Z19D 블록은 직접 측정한 CO₂**이며 시작 후 60초 동안 -1입니다.
- OLED 기본은 SSD1306입니다. 실제 칩이 SH1106인 경우만 바꿉니다. 화면 크기로 칩을 단정하지 않습니다. LCD·OLED 텍스트는 영어·숫자만 지원합니다.
- 사용자가 확정한 초음파 핀 순서는 **G–V–ECHO–TRIG**입니다. 예를 들어 DSL의 G/V/P13/P14 단자라면 에코=P13, 트리거=P14를 선택합니다. 5V ECHO 신호는 전압 변환이 필요합니다. 블록은 모듈 핀 순서와 같게 **에코 → 트리거** 순서이고 기본값이 에코=P13·트리거=P14입니다. 반사가 없으면 최대 3번 다시 쏜 뒤 -1을 돌려줍니다. HC-SR04는 **5V 전원**이 필요하므로 5V 단자(DSL은 P13·P14)에 꽂습니다.
- PMS·MH-Z19D·GPS·AS608은 V2 센서용 UART 하나를 공유합니다. **마지막에 시작한 센서 하나만 읽으며 다른 센서는 실패값**을 반환합니다(GPS -9999, 나머지 -1). USB115200 송신은 별도 UART에서 유지합니다. RX/TX는 micro:bit 기준이며 센서 TX→RX, 센서 RX→TX입니다. UART 센서 시작 블록은 시작할 때 한 번 실행합니다. GPS/AS608의 통신 속도 메뉴는 모듈 설정을 변경하지 않고 micro:bit의 속도를 맞춥니다.
- **PMS3003은 3핀(G·V·TX, 신호선 1개)**이라 `미세먼지 센서 PMS3003 시작 핀 ( )` 블록으로 신호선이 꽂힌 핀 하나만 고릅니다. **PMS7003은 4핀(G·V·TX·RX)**이라 `미세먼지 센서 PMS7003 시작 RX ( ) TX ( )` 블록을 씁니다.
- PMS는 전원 공급 후 기본 자동 송신 모드를 사용합니다. 처음 30초, 체크섬 오류, 3초 이상 수신 없음은 -1입니다. 모듈을 수동 모드로 바꿨다면 전원을 다시 켜 기본 자동 모드로 돌아온 뒤 사용합니다.
- GPS는 보유 D_031/D_032 모듈·안테나의 NMEA RMC/GGA 출력용입니다. 칩셋명은 확정하지 않았습니다. 위도·경도(소수점 도), 고도(m), 속도(km/h), 위성 수를 읽습니다. 기본 속도 9600, 각 항목은 3초 이상 갱신되지 않으면 -9999입니다. 위치 확인은 실외에서 먼저 시험합니다.
- 지문 AS608은 기본 비밀번호 0·주소 FFFFFFFF·통상 57600 baud 조건입니다. 같은 손가락을 **1차 등록 → 손가락 떼고 다시 대기 → 같은 번호로 2차 등록** 순서로 등록합니다(60초 이내). 2차 등록까지 성공하면 센서에 저장됩니다. 번호는 1부터 센서 저장 용량 미만이며 같은 번호는 덮어씁니다. 실행 직후 지문 상태 코드로 결과를 확인합니다. 인식 블록은 등록 번호를 반환하고 이미지·지문 특징 데이터는 송신하지 않습니다. 상태 0=성공, 2=손가락 없음, 9=일치 없음, 10=두 지문 불일치, -1=설정·통신·입력 오류입니다. 통신 오류 후 시작 블록을 다시 실행합니다.
- A_016/017/018 아날로그 먼지 세트는 **센서 5V 전원·VO 분압·전압에 맞는 LED 구동 회로**를 전제로 합니다. Sharp GP2Y1010 계열의 280µs 샘플/320µs LED 펄스 조건으로 직접 ADC를 읽고 8회 평균 원시값 0~1023을 반환합니다. 소제목에는 미확정 모델명을 붙이지 않습니다. PM2.5·µg/m³ 환산은 하지 않습니다. 마이크 등 ADC 스트리밍과 동시 사용하거나 펄스 타이밍을 놓치면 -1입니다. 실물 회로와 파형 검증은 남아 있습니다.
- MQ 가스 9종은 사용자 결정에 따라 MakeCode 기본 **핀 → 아날로그 값 읽기** 블록을 사용합니다. 모듈 출력이 micro:bit 입력 범위를 넘지 않도록 연결하며 원시값을 가스 농도 ppm으로 표시하지 않습니다.
- 탁도·전압은 **선택한 마이크로비트 아날로그 핀의 0~1023 원시값**을 읽습니다. 원시값 블록은 보정이 필요 없습니다. 센서 모듈의 출력 신호는 0~3.3V이면서 보드 전원 이하여야 합니다. 모듈 전원 전압과 출력 신호 전압을 구분합니다.
- 탁도 보정은 맑은 물의 원시값을 100%로 저장합니다. 작아질수록 흐린 물이며 NTU가 아닙니다. 전압은 분압 모듈을 통해 기준 계기로 확인한 직류 전압을 보정하고 같은 핀의 원시값에서 V를 계산합니다. 모듈의 25V 표기가 마이크로비트의 측정 한도를 뜻하지 않으며 실제 한도는 분압비와 핀 입력 전압에 따라 달라집니다. 측정 전압을 마이크로비트 핀에 직접 연결하지 않습니다.
- 두 센서의 보정은 핀별로 저장되고 재시작하면 사라집니다. 보정 기준 원시값은 5~1022여야 합니다. 잘못된 재보정은 해당 핀의 이전 보정을 지웁니다. 보정 전·입력 포화(1023)는 보정값 블록에서 -1을 반환하며 원시값 블록에서는 1023을 그대로 볼 수 있습니다. 아날로그 센서 미연결은 확실히 식별할 수 없습니다.
- MAX30102는 20~100ms마다 읽는 광학 원시값이며 심박수·SpO₂가 아닙니다. EC11은 손으로 천천히 돌리는 신호 주기 수이며 빠른 회전은 놓칠 수 있습니다. APDS9960 방향은 0 없음/1 위/2 아래/3 왼쪽/4 오른쪽이고 한 번 읽으면 지워집니다.
- DS1307은 `RTC 시계 (12)시 (0)분 (0)초로 설정`으로 시간을 맞추고 작동시킵니다. 24시간제이며 정지 비트(CH)도 해제합니다. 설정은 시간을 맞출 때 한 번 실행하세요. 무한반복에 넣으면 계속 같은 시각으로 돌아가고, 시작하면에 넣으면 보드를 재시작할 때마다 다시 맞춰집니다. 읽기 블록은 시·분·초를 반환하며 정지·잘못된 시계 값·읽기 오류는 -1입니다. 유효한 기존 날짜는 유지하고 잘못된 날짜만 2000-01-01로 초기화합니다(날짜를 현재 날짜로 맞추는 기능은 아님). TypeScript의 `trySetClock(hour, minute, second)`는 입력/I2C 오류 시 false를 반환합니다. 설정 실패 시 배선을 확인하고 다시 설정하세요. [DS1307 데이터시트](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1307.pdf)의 시간 레지스터 규칙을 따릅니다.
- MPU6050/DS1307(0x68), TCS34725/VL53L0X(0x29), MLX90614/CCS811(0x5A)은 같은 주소끼리 직접 병렬 연결하지 않습니다.

## 센서별 보정·단위·값 해석

### 1. 원시값과 실제 물리량

마이크로비트 아날로그 입력의 반환 범위는 **0~1023, 총 1024단계**입니다. `1024`가 최댓값은 아닙니다. 이 숫자는 센서 출력 전압의 크기를 나타내는 ADC 코드이며 그 자체가 온도·조도·소음·무게는 아닙니다. 단순 아날로그 블록의 문구도 `원시값`으로 명확히 했습니다. 이전 버전의 `측정값`과 같은 값입니다. 입력 범위와 API는 [MakeCode analogReadPin](https://makecode.microbit.org/reference/pins/analog-read-pin)을 참고합니다.

`r`=원시값, `r0`=영점 원시값, `r1/r2`=기준점에서 읽은 원시값, `x1/x2`=기준 계기로 확인한 물리량으로 씁니다.

| 목적 | 식 | 적용 조건 |
|---|---|---|
| 핀 전압의 대략적 환산 | `Vpin ≈ r × VFS / 1023` | 이 프로젝트의 아날로그 환산은 VFS=3.3V를 가정. 전원·ADC 오차가 있으므로 정확한 V는 기준 전압 보정 사용 |
| 영점에서의 변화 | `Δr = r - r0` | 단위는 여전히 ADC 코드. 음수가 나올 수 있으며 물리 단위를 붙이지 않음 |
| 두 점 선형 환산 | `x = x1 + (r-r1) × (x2-x1)/(r2-r1)` | `r1≠r2`, 해당 구간에서 선형이라는 근거 필요. 두 기준 사이에서 사용하고 제3의 값으로 검증 |
| 상대 척도 | `q = 100 × (r-r0)/(r100-r0)` | 사용자 정의 0~100 척도. 실제 수분 함량·반사율 등을 자동으로 뜻하지 않음 |
| 임계값 감지 | `r`과 두 상태 중간의 기준값 비교 | 움직임·빛·물의 유무 판단. 채터링 방지를 위해 켜짐/꺼짐 기준을 조금 다르게 설정할 수 있음 |

예를 들어 기준 전압 5V를 모듈에 넣었을 때 원시값이 400이라면 같은 배선에서 `입력 전압 = r × 5 / 400`입니다. **5V를 마이크로비트 핀에 직접 넣는다는 뜻이 아닙니다.** 분압 모듈을 거친 핀의 신호가 입력 한도 이하여야 합니다. 실제 입력 한도는 분압비·전원·배선으로 결정됩니다.

센서가 빠져도 아날로그 핀이 임의의 숫자를 읽을 수 있습니다. 0이나 1023 하나만으로 연결 여부를 확정할 수 없습니다. 포화된 1023을 더 큰 물리량으로 환산하지 마세요. -1/-127/-999/-9999 같은 실패값을 먼저 검사하고 나서 식을 적용합니다. `%` 표시는 같은 의미가 아닙니다: 상대습도, 토양 상대척도, 탁도 출력비를 구분하세요.

### 2. 공통 보정·정확도 확인 순서

1. 기준 계기/표준물질의 단위·유효기간·정확도, 센서 전원·배선·장착·예열 조건을 확인합니다. 온도나 물이 닿는 실험은 모듈의 실제 정격을 따릅니다.
2. 보정 블록은 기준물질이 안정된 상태에서 버튼 등으로 한 번 실행합니다. **보정 명령을 무한반복에 넣지 않습니다.** 공기질 온습도 보상은 환경 변화에 맞춰 주기적으로 갱신하는 예외입니다.
3. 영점과 기준점으로 보정하고, **보정에 쓰지 않은 중간값 및 다른 기준값**에서 각각 10회 이상 비교합니다. 저·중·고 3개 이상 조건에서 같은 방향/반대 방향으로 확인하면 비선형성과 이력 차이도 드러납니다.
4. 기준값, 원시값, 보정값, 평균, 최소·최대, 오차를 기록합니다. `오차=측정값-기준값`, `상대오차(%)=100×오차/기준값`이며 기준값이 0이면 상대오차를 쓰지 않습니다. 허용 오차는 실험 목적과 실제 모듈/기준 계기 사양으로 정합니다.
5. 센서·핀·전원·배선·장착·용액 온도를 바꾸면 다시 보정합니다. 이 확장의 소프트웨어 보정은 RAM에 있어 **재시작하면 사라집니다.** RTC 시간과 AS608 지문 저장은 센서 자체의 별도 상태입니다.

아날로그 기준점은 16회·약 80ms를 읽어 심한 흔들림(최댓값−최솟값>20코드)을 거절합니다. 이것은 짧은 안정성 검사이며, 용액 안정화나 센서 예열을 대신하지 않고 정확도를 보증하는 기준도 아닙니다. pH는 **7→4 또는 7→10**, PT100은 **첫 기준→둘째 기준**, 토양은 **마른 흙→젖은 흙** 순서입니다. 첫 기준을 다시 잡으면 이전 둘째 기준을 무효화합니다. 잘못된 재보정 뒤 실패값이 나오면 조건을 고쳐 다시 보정하세요.

### 3. 아날로그 센서별 준비물·변환·해석

#### 조도 센서

- **블록/API:** 조도 (`light`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 기준 조도계, 밝기가 다른 여러 조건. 같은 위치·방향에서 `r↔lux` 표를 만들고 모듈 특성에 맞는 곡선/구간 보간 사용
- **값 해석·한계:** 광저항은 보통 비선형. `r×상수`로 lux를 확정하지 않음. 현재 블록은 밝기 변화용

**계산·판단 예:** 조도계와 비교해 원시값 200=100lux, 600=500lux이고 그 사이가 선형임을 확인했다면, 400은 300lux로 보간할 수 있습니다. 이 숫자는 계산 예이며 다른 모듈에 그대로 적용하지 않습니다.

#### 자외선 센서

- **블록/API:** 자외선 (`uvRaw`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 기준 UV 계기, 정확한 센서 모델·파장 응답·증폭도. 출력 기울기가 확인된 선형 모듈만 `E=(V-Vdark)/감도`
- **값 해석·한계:** UV 강도와 UV 지수는 다름. 정확한 감도·파장 가중치가 없으므로 현재 블록은 원시값

**계산·판단 예:** 어두울 때 100, 빛을 비출 때 300이면 변화량은 200코드입니다. 이것만으로 UV 지수 2 또는 200을 뜻하지 않습니다. E는 복사조도, Vdark는 어둠 출력 전압이며 감도의 단위를 먼저 확인합니다.

#### 소리 센서

- **블록/API:** 소리 (`sound`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 소음계 또는 음향 교정기, 고정 거리. 출력이 AC 파형인지 정류된 크기인지 먼저 확인
- **값 해석·한계:** 단일 원시값은 dB가 아님. AC라면 DC 중심을 뺀 일정 시간의 RMS가 필요. 동일 주파수·이득 조건에서만 `L=Lref+20log10(Arms/Aref)`를 검토; 현 블록은 RMS/주파수 가중치를 계산하지 않음

**계산·판단 예:** 조용할 때 500, 소리가 날 때 550이었다면 원시값이 50 변한 것입니다. 소음이 50dB 커졌다는 뜻이 아닙니다. 위 식의 Arms/Aref는 같은 시간창·주파수·증폭 조건에서 구한 유효 진폭의 비입니다.

#### 토양 수분 센서

- **블록/API:** 토양 수분 (`soilMoisture`, `soilMoisturePercent`)
- **현재 값·단위:** 원시값 / 상대 0~100
- **준비물·보정과 변환:** 같은 흙 두 시료, 일정한 삽입 깊이. 마른 흙 보정→젖은 흙 보정→상대 수분 읽기. `100(r-rdry)/(rwet-rdry)`
- **값 해석·한계:** 실제 체적 수분율이 아님. 흙 종류·다짐·염도·전극 부식 영향. 기준 범위 밖 -1

**계산·판단 예:** 마른 흙=800, 젖은 흙=200, 현재=500이면 100×(500−800)/(200−800)=50입니다. 이 50%는 두 기준 사이의 상대 수분입니다.

#### 물 감지 센서

- **블록/API:** 물 감지 (`water`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 같은 물, 센서의 허용 침수 범위, 자. 마른 상태와 여러 수위에서 표 작성
- **값 해석·한계:** 전극 젖은 면적과 물 전도도 영향. 물 높이 cm·물의 양 L로 일반 변환 불가. 검증한 동일 조건에서만 구간 보간

**계산·판단 예:** 마른 상태 100, 물이 닿을 때 600이라면 두 상태 사이의 350을 감지 기준으로 시험할 수 있습니다. 전도도가 다른 물에서는 기준을 다시 잡습니다.

#### 빗물 센서

- **블록/API:** 빗물 (`rain`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 깨끗하고 마른 판, 같은 방향, 일정량 물방울. 마름/젖음 기준으로 상대척도·임계값 설정
- **값 해석·한계:** 판의 젖음 정도이며 강우량 mm가 아님. 강우량에는 집수 면적과 계량 구조 필요

**계산·판단 예:** 마른 판=900, 젖은 판=300일 때 현재 600은 상대 젖음 50입니다. 비가 50mm 내렸다는 뜻은 아닙니다.

#### pH 센서

- **블록/API:** pH (`ph`)
- **현재 값·단위:** pH
- **준비물·보정과 변환:** pH 7 + 4 또는 10 표준용액, 세척용 순수, 온도계. 7→4(산성) 또는 7→10(알칼리성) 보정. `7+(pHref-7)(r-r7)/(rref-r7)`
- **값 해석·한계:** 용액 라벨의 온도별 pH와 맞는 조건 사용. 6.86/9.18 용액을 7/10으로 입력하지 않음. 전극 온도 보상은 별도 구현하지 않음. 기준 밖은 외삽이며 검증 필요

**계산·판단 예:** pH7에서 500, pH4에서 700, 현재 600이면 7+(4−7)×(600−500)/(700−500)=5.5입니다. 센서 극성이 반대여도 실제 기준 원시값으로 계산합니다.

#### TDS 센서

- **블록/API:** TDS (`tds`)
- **현재 값·단위:** 25°C 기준 ppm 추정
- **준비물·보정과 변환:** TDS 표준용액, 수온계, 세척용 순수. `기준 용액 ppm·실제 수온 보정` 후 실제 수온을 넣고 읽기. 기본 예 707ppm(환산계수0.5), 0~50°C
- **값 해석·한계:** 아래 식 사용. EC(µS/cm)와 ppm을 혼동하지 않음. 용액/계기 환산계수 일치 필요. 보정 전·1000ppm 초과 -1. 실제 용존 물질 조성까지 알아내는 센서가 아님

**TDS 계산 상세:** `V=r×3.3/1023`, `f(V)=133.42V³-255.86V²+857.39V`, `estimate=0.5f(V)/(1+0.02(T-25))`, `gain=기준용액ppm/estimate(보정 시)`, 최종 `ppm=gain×estimate`. 전압을 먼저 온도로 나누던 이전 방식을 전도도 환산 뒤 온도 보상하는 방식으로 바꿨습니다. 이 식은 [DFRobot Gravity TDS의 변환·보정 방식](https://github.com/DFRobot/GravityTDS/blob/master/GravityTDS.cpp)을 참고한 **호환 모듈 가정**이며 보유 모듈에서 표준용액 여러 점으로 검증해야 합니다. 0.5 계수의 1413µS/cm는 706.5ppm이고 제품 안내에서 약 707ppm으로 표기됩니다. 0.7 계수로 표시한 다른 TDS 계기와 그대로 비교하지 마세요.

#### 탁도 센서(AZDM01)

- **블록/API:** 탁도 (`turbidityRaw`, `turbidity`)
- **현재 값·단위:** 원시값 / 맑은 물 대비 출력비
- **준비물·보정과 변환:** 깨끗한 동일 용기, 맑은 물, 차광. 맑은 물 보정 후 `100r/rclear`
- **값 해석·한계:** 블록의 ‘투과율’은 센서 출력의 상대비. 광학 투과율을 공인 측정한 값이나 NTU가 아님. NTU에는 표준 탁도액 여러 점·모듈별 곡선 필요. 0~120 범위, 초과 -1

**계산·판단 예:** 맑은 물 기준 800, 현재 400이면 상대 출력비 50%입니다. 50NTU가 아닙니다.

#### 아날로그 진동 센서

- **블록/API:** 진동 (`scienceMotion.vibration`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 고정 지그, 정지 기준·일정한 진동 조건. 기준값을 빼거나 구간별 변화폭 비교
- **값 해석·한계:** 샘플 속도·진동 주파수 영향. 이 블록 하나로 가속도 g·진동 속도 mm/s를 얻지 못함

**계산·판단 예:** 정지 기준 500에서 순간 620이면 변화량은 +120코드입니다. 여러 시점의 최댓값−최솟값으로 흔들림을 비교할 수 있지만 g 단위는 별도 감도와 시간 측정이 필요합니다.

#### 자석 센서

- **블록/API:** 자석 (`magnet`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 자석 없는 기준, 가우스미터, 고정 방향·거리. 선형 Hall 감도가 확인되면 `B=(V-Vzero)/감도`
- **값 해석·한계:** 모델별 감도와 전원 의존성 확인 필요. 거리나 mT로 일반 변환 불가

**계산·판단 예:** 자석 없는 기준 510에서 현재 610이면 +100코드입니다. B는 자속밀도이며, V/mT 등의 모듈 감도가 확인되기 전에는 이 변화에 mT를 붙이지 않습니다.

#### 압력·힘 센서

- **블록/API:** 압력/힘 (`force`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 기준추 또는 힘 측정기, 일정한 접촉 면적·지그. 여러 힘과 원시값의 관계표 작성
- **값 해석·한계:** 힘 N와 압력 Pa를 구분. 질량 m(g)에 가해지는 힘은 대략 `F=m×9.80665/1000 N`, 압력은 `F/면적(m²)`. FSR의 비선형·히스테리시스로 단순 2점 환산은 국소 구간에서만 검증

**계산·판단 예:** 100g 기준추가 수직으로 누르는 힘은 약 0.981N입니다. 그때의 원시값과 200g 등 여러 점을 기록해 곡선을 만듭니다. 원시값이 2배라고 힘이 2배라고 가정하지 않습니다.

#### 회전 센서

- **블록/API:** 회전 (`rotation`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 각도기·기계적 끝점. 알려진 두 각도 사이에서 선형 환산
- **값 해석·한계:** 선형 포텐셔미터의 확인된 회전 구간에만 적용. 무조건 `r×360/1023`은 잘못될 수 있음

**계산·판단 예:** 실제로 확인한 0°에서 100, 270°에서 900이고 선형이라면 원시값 500은 135°입니다. 회전 범위 270°는 계산 예이며 실제 모듈의 끝점으로 바꿉니다.

#### 무한 회전 센서

- **블록/API:** 무한 회전 (`infiniteRotation`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 각도 표시판, 천천히 한 바퀴 돌려 출력·끊김점 기록
- **값 해석·한계:** 반복/끊김 구간 때문에 한 숫자만으로 누적 회전 횟수를 알 수 없음. 누적 횟수는 EC11 사용

**계산·판단 예:** 한 바퀴에서 값이 올라가다 갑자기 떨어지는 구간을 먼저 찾습니다. 동일 원시값이 여러 회전에서 반복되므로 원시값만으로 누적 각도를 계산하지 않습니다.

#### 슬라이더

- **블록/API:** 슬라이더 (`slider`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 자, 두 위치 기준. `위치=x1+(r-r1)(x2-x1)/(r2-r1)`
- **값 해석·한계:** 선형 출력·같은 장착 구간을 확인한 경우에만 mm 등 단위 사용

**계산·판단 예:** 0mm에서 100, 60mm에서 900이고 선형이라면 현재 500은 30mm입니다. 슬라이더의 실제 이동 길이를 기준으로 정합니다.

#### 조이스틱

- **블록/API:** 조이스틱 (`joystick`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 중심·양쪽 끝 원시값 기록. 중심 이상은 `100(r-center)/(max-center)`, 이하는 `100(r-center)/(center-min)`
- **값 해석·한계:** 결과 -100~100은 조작량. 중심 근처 불감대를 둘 수 있음. 각도·힘 아님

**계산·판단 예:** 중심=500, 오른쪽 끝=900, 현재=700이면 조작량 +50입니다. 왼쪽 끝=100, 현재=300이면 −50입니다. 중심 주변의 작은 흔들림은 불감대로 처리합니다.

#### 4패드 아날로그 터치

- **블록/API:** 4패드 터치 (`analogTouch`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 각 패드를 하나씩 누른 값과 안 누른 값 기록, 값 구간으로 패드 판별
- **값 해석·한계:** 저항 사다리의 패드 식별값. 압력·접촉 면적 환산 불가, 복수 패드는 별도 시험

**계산·판단 예:** 패드마다 기록한 원시값 구간에 이름을 붙입니다. 예를 들어 특정 패드가 항상 240~270이면 이 구간을 그 패드의 조건으로 사용합니다. 이 범위는 실제 측정값으로 대체합니다.

#### 라인 센서

- **블록/API:** 라인 (`line`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 흰/검은 표면, 일정한 높이·조명. 두 기준 상대척도 또는 임계값
- **값 해석·한계:** 결과는 그 설치 조건의 상대 반사 신호. 실제 반사율/거리 아님

**계산·판단 예:** 검정=200, 흰색=800이라면 500을 경계로 시험하고, 480 아래/520 위처럼 서로 다른 전환 기준을 두어 깜박임을 줄일 수 있습니다. 높이·조명이 바뀌면 다시 정합니다.

#### 적외선 물체 감지 센서

- **블록/API:** 적외선 물체 (`object`)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 같은 재질의 표적, 자, 여러 거리. 실측 표나 모델 특성식 사용
- **값 해석·한계:** 거리·색·각도·주변광이 함께 영향. `1023-r` 같은 식으로 cm를 만들지 않음

**계산·판단 예:** 5·10·15cm 등 알려진 거리에서 원시값을 기록하고 반복성이 있는 구간만 사용합니다. 같은 원시값이 여러 거리에서 나오면 그 구간은 한 값으로 거리를 결정할 수 없습니다.

#### 온도 센서(NTC)

- **블록/API:** NTC (`ntc`)
- **현재 값·단위:** °C
- **준비물·보정과 변환:** 기준 온도계, 잘 섞인 안정된 온도 환경. `NTC 기준 온도 보정` 후 다른 온도에서 비교
- **값 해석·한계:** `R=10000(1023/r-1)`, `T=1/[1/298.15+ln(R/R25)/3950]-273.15`. 보정은 R25만 조정. 10kΩ 하단 저항·위쪽 B3950 NTC 조건; 반대 배선·다른 B값에는 적용 불가

**계산·판단 예:** 명목 R25=10000Ω이고 원시값이 약 511.5이면 식의 결과는 약 25°C입니다. 블록은 온도로 환산한 값을 이미 반환하므로 결과에 다시 이 식을 적용하지 않습니다.

#### 온도 센서(PT100)

- **블록/API:** PT100 (`pt100`)
- **현재 값·단위:** °C
- **준비물·보정과 변환:** 기준 온도계, 실험 구간의 두 안정된 온도. 첫·둘째 기준 보정 후 중간 온도로 확인
- **값 해석·한계:** 두 점 선형식. 첫·둘째 온도 차이≥1°C, 원시값 차이≥5. 두 점 사이에서만 읽기. 모듈·프로브 실제 정격 우선

**계산·판단 예:** 20°C에서 200, 60°C에서 600으로 보정했다면 원시값 400은 40°C입니다. 블록은 이 계산을 수행하며 두 기준 온도 밖은 −9999를 반환합니다.

#### 전류 센서(WCS2801)

- **블록/API:** 전류 WCS2801 (`current`)
- **현재 값·단위:** DC A
- **준비물·보정과 변환:** 멀티미터, 안정된 전원·부하. 전류를 끊고 영점→기준 전류 보정. `I=(r-rzero)×Iref/(rref-rzero)`
- **값 해석·한계:** ±1A 이내의 직류용. 교류 RMS 아님. 영점을 새로 맞추면 기준 전류도 다시 보정

**계산·판단 예:** 0A에서 500, 기준 0.5A에서 700, 현재 600이면 (600−500)×0.5/(700−500)=0.25A입니다. 전류 방향도 기준과 일치시킵니다.

#### 전압 센서

- **블록/API:** 전압 (`voltageRaw`, `voltage`)
- **현재 값·단위:** 원시값 / DC V
- **준비물·보정과 변환:** 멀티미터, 안전한 기준 전압, 분압 모듈. 기준 전압 보정 후 `V=r×Vref/rref`
- **값 해석·한계:** 영점 0을 가정한 1점 비례식. 무전압 오프셋이 크면 배선·회로를 점검하고 2점 특성을 별도 검증. 핀 입력 한도 준수

**계산·판단 예:** 분압 모듈에 기준 5V를 인가했을 때 400이었다면 현재 200은 2.5V입니다. 기준 5V는 모듈 입력 전압이며 micro:bit 핀에 직접 넣지 않습니다.

#### 아날로그 미세먼지 센서

- **블록/API:** 아날로그 미세먼지 (`analogDust`)
- **현재 값·단위:** 펄스 동기 ADC 0~1023
- **준비물·보정과 변환:** 정확한 모델 자료, 정상 전원·분압, 깨끗한 공기, 기준 입자계, 가능하면 오실로스코프
- **값 해석·한계:** 깨끗한 공기 기준 `r-r0`는 변화량만 의미. 모델별 감도·기준 입자 없이 µg/m³·PM2.5로 환산하지 않음. 펄스/회로 검증도 필요

**계산·판단 예:** 깨끗한 공기 기준 120, 현재 170이면 변화량 50코드입니다. 이 값을 50µg/m³ 또는 PM2.5 농도로 표시하지 않습니다.

#### MQ 가스 센서 공통 환산

- **블록/API:** MQ 가스 9종(기본 핀 블록)
- **현재 값·단위:** 0~1023
- **준비물·보정과 변환:** 정확한 MQ 모델, 히터·부하저항 회로, 충분한 예열, 해당 가스 표준 농도

### 4. 디지털·I2C·UART 센서별 보정과 준비물

#### 온습도 센서(GXHT30·SHT30·SHT31)

- **준비물·확인 순서:** 기준 온습도계, 같은 위치·통풍·충분한 안정화. 여러 온도/습도에서 비교
- **값 해석·보정 방법:** 제조 보정값·CRC를 사용. 현재 블록은 °C/%RH. 기준기 없이 임의 0점 조정하지 않음. 체계적 오차가 실측되면 한 점 차이 보정의 적용 구간을 별도 확인

#### 온습도 센서(DHT11·DHT22)

- **준비물·확인 순서:** 기준 온습도계, 결로 없는 안정된 환경. 같은 모델을 정확히 선택
- **값 해석·보정 방법:** 공장 환산값. 응답 지연·해상도와 정확도는 다름. 측정 간격·통신 체크섬 확인, 온습도 여러 점에서 비교

#### 수온 센서(DS18B20)

- **준비물·확인 순서:** 기준 온도계, 섞인 물, 같은 깊이·충분한 대기. 프로브마다 비교
- **값 해석·보정 방법:** °C, CRC·변환 완료 확인. 여러 프로브 번호는 소켓 번호가 아님. 프로브별 오차를 확인하며 방수 정격 우선

#### 비접촉 온도 센서(MLX90614)

- **준비물·확인 순서:** 기준 온도계/흑체, 무광 표적, 일정 거리·시야. 접촉 기준기는 같은 표적에 접촉
- **값 해석·보정 방법:** 물체/주변 °C. 방사율·표적 크기·반사 영향은 단순 영점으로 해결 안 됨. 반짝이는 금속에 맞춰 전 범위 상수를 덮어쓰지 않음. EEPROM 방사율은 변경하지 않음

#### 기압 센서(BMP280)

- **준비물·확인 순서:** 기준 기압계, 지역 해면기압(QNH), 알려진 높이
- **값 해석·보정 방법:** 공장 계수로 hPa/°C 환산. `고도 기준 해면기압` 추가. `h=44330[1-(P/P0)^0.1903]`. 날씨·기준 기압 영향 때문에 GPS 고도와 같은 정확도를 보장하지 않음

#### 자이로 센서(MPU6050)

- **준비물·확인 순서:** 고정 지그, 충분한 안정화 후 가만히 두고 영점 맞추기
- **값 해석·보정 방법:** 50회 평균, 움직임이 크면 실패(-999). °/s의 정지 오프셋 보정. 일정한 회전 중에는 보정하지 않음

#### 가속도 센서(MPU6050)

- **준비물·확인 순서:** 수평·수직 지그. X/Y/Z 각각 +축을 위로(+1g)→아래로(-1g), 총 6회
- **값 해석·보정 방법:** `가속도 축 보정` 추가. 축마다 `a=2(raw-mid)/(plus-minus)`로 offset/scale 보정. 정지 시 벡터 크기 약 1g, 자유낙하 약 0g. 중력을 0으로 지우지 않음. 축 비직교성 보정은 아님

#### I2C 무게 센서

- **준비물·확인 순서:** 빈 접시/용기, 정격 이내의 기준추, 안정된 수평 받침
- **값 해석·보정 방법:** `빈 접시 영점→기준 무게 g 보정→무게(g)` 추가. `g=(r-r0)×gref/(rref-r0)`. `무게 모듈 원시값`은 단위 미확정. PEEL 버튼·모듈 재시작·장착 변경 후 재보정. 기준추 이하에서 사용

#### 초음파 거리 센서

- **준비물·확인 순서:** 자, 평평한 표적, 주변 온도계, 고정 지그
- **값 해석·보정 방법:** `주변 온도 보정` 후 필요하면 `기준 거리 보정`. 공기 중 `d(cm)=echo(µs)×(331+0.6T)/20000 + offset`. 큰 설치오차·불안정 반사 거절. 천/비스듬한 표적·사각에서는 별도 시험

#### 레이저 거리 센서(VL53L0X)

- **준비물·확인 순서:** 자, 무광 표적, 덮개 없는 센서. 100~500mm에서 기준값 입력
- **값 해석·보정 방법:** 시작 시 내부 기준 보정 유지. 추가 블록은 평균 출력의 작은 offset만 보정. 다른 거리로 재검증. 보호유리 크로스토크 보정은 별도 장치·ST 절차가 필요하며 이 블록이 대체하지 않음

#### 색상 센서(TCS34725)

- **준비물·확인 순서:** 흰색·검은색·색 표준표, 일정한 광원·높이·각도
- **값 해석·보정 방법:** R/G/B/C는 카운트. `100(channel-dark)/(white-dark)`는 그 조건의 상대 색 강도이며 lux/색차/sRGB가 아님. 포화와 광원 변화 확인

#### 근접 센서(APDS9960)

- **준비물·확인 순서:** 같은 반사 표적·거리 지그
- **값 해석·보정 방법:** 0~255 원시값, cm 아님. 표적 재질·각도별 거리표/임계값으로 실험

#### 색상 센서(APDS9960)

- **준비물·확인 순서:** 색 표준표·같은 광원과 거리
- **값 해석·보정 방법:** R/G/B/C 원시값. TCS34725처럼 어둠/흰색 기준 비교, 서로 다른 센서의 카운트끼리 직접 비교하지 않음

#### 손짓 센서(APDS9960)

- **준비물·확인 순서:** 모듈 방향 표시, 일정 거리의 반복 동작
- **값 해석·보정 방법:** 방향 번호는 분류 결과. 위/아래/좌/우의 성공 횟수와 실패를 기록. 영점·물리량 환산 대상 아님

#### eCO2 센서(SGP30)

- **준비물·확인 순서:** 기준 온습도계 또는 SHT계열, 환기·충분한 사용 시간
- **값 해석·보정 방법:** `주변 온도·습도 보상` 추가. 1Hz 측정과 내부 기준선 알고리즘 유지. 처음 15초가 지났다고 장기 안정화가 끝난 것은 아님. TVOC ppb/eCO₂ ppm은 추정, 실제 CO₂와 동일하지 않음

#### eCO2 센서(CCS811)

- **준비물·확인 순서:** 기준 온습도계, nWAKE LOW, 충분한 예열
- **값 해석·보정 방법:** `주변 온도·습도 보상` 추가. 시작 후 20분과 최초 사용 burn-in을 구분. 추정 eCO₂를 기준 CO₂ 계기의 값에 단순 선형 보정하지 않음

#### CO2 센서(MH-Z19D)

- **준비물·확인 순서:** 비교용 CO₂ 계기, 규격 전원, 충분한 예열·같은 공기 환경
- **값 해석·보정 방법:** ppm 직접 측정. 고농도/저농도에서 독립 비교. 현재 확보한 제조사 D 문서에는 UART 보정 명령표가 없어 0x87/ABC 등 다른 모델의 쓰기 명령을 추정해 넣지 않음. 제조사 D 전용 절차·기준가스 확인 후 수행. 실내 공기를 임의로 400ppm으로 맞추지 않음

#### 미세먼지 센서(PMS3003·PMS7003)

- **준비물·확인 순서:** 비교 입자계, 같은 공기·흡기 위치·습도, 충분한 예열
- **값 해석·보정 방법:** PM1/PM2.5/PM10 µg/m³는 모듈 알고리즘 값. 입자 조성·습도 영향. 모듈의 범용 사용자 보정 명령은 확인되지 않았으며 기준 입자/챔버 없이 질량농도 보정 계수 확정 불가

#### 심박 센서(MAX30102)

- **준비물·확인 순서:** 일정한 손가락 위치·접촉 압력·차광, 가만히 유지
- **값 해석·보정 방법:** 적색/적외선 맥파 원시값. bpm·SpO₂가 아니며 0점 조정으로 산소포화도를 만들 수 없음. 움직임·광량 포화와 맥파 모양을 확인

#### 로터리 인코더(EC11)

- **준비물·확인 순서:** 손잡이 시작점 표시·느린 회전
- **값 해석·보정 방법:** 시작 후 `횟수 0 맞추기`. 값은 디코딩된 신호 주기 수. 360° 환산은 실제 1회전에 몇 주기인지 실측 후 `각도=count×360/실측주기수`

#### GPS 센서

- **준비물·확인 순서:** 실외 시야·안테나, 알려진 위치/거리
- **값 해석·보정 방법:** 위도·경도 도, 고도 m, 속도 km/h, 위성 수. 수신 유효성·산포 검사. 임의 영점으로 절대 위치 정확도를 높이지 않음

#### 시계(DS1307)

- **준비물·확인 순서:** 기준 시계, 모듈 전원·백업 배터리
- **값 해석·보정 방법:** `시·분·초로 설정` 후 읽기, 다음 날 시간차 측정. 시간 설정과 주파수 오차 보정은 다름. RTC가 계속 움직이는지·전원 복구 후 유지 여부 확인

#### 지문 센서(AS608)

- **준비물·확인 순서:** 같은 손가락, 깨끗한 센서 표면
- **값 해석·보정 방법:** 1차→손가락 떼고 다시 대기→2차 등록. 번호·상태는 물리량이 아님. 등록/미등록 손가락으로 인식 성공·오인식·거절 시험


공기질 보상 구현은 [SGP30 제조사 데이터시트](https://sensirion.com/media/documents/984E0DD5/61644B8B/Sensirion_Gas_Sensors_Datasheet_SGP30.pdf)와 [CCS811 제조사 문서](https://cdn.sparkfun.com/assets/learn_tutorials/1/4/3/CCS811_Datasheet-DS000459.pdf)를 따릅니다. 초음파 음속 관계는 [TI 응용 문서](https://www.ti.com/lit/an/slaa732a/slaa732a.pdf), 레이저 보정 구분은 [ST VL53L0X 문서](https://www.st.com/resource/en/datasheet/vl53l0x.pdf)를 참고했습니다. MH-Z19D 명령 확인 범위는 [제조사 D 모델 매뉴얼](https://www.winsen-sensor.com/d/files/manual/mh-z19d.pdf)과 [SOURCES.md](SOURCES.md)에 명시했습니다.

### 5. 0/1 감지 센서와 출력 장치

아래 센서는 **전기 신호 0 또는 1**을 반환합니다. 거리·온도 등의 연속 물리량 보정이 아니라 감지 극성·임계값·장착 조건을 확인합니다. 모듈에 조절 나사가 있으면 기준 상황에서 조절하고 전후 상태를 기록합니다.

#### 버튼

- **준비물·확인 순서:** 손으로 누르기/놓기 각 10회
- **값 해석·보정 방법:** 눌렀을 때 0인지 1인지 확인, 접점 튐 확인

#### 락커 스위치

- **준비물·확인 순서:** 두 위치를 번갈아 선택
- **값 해석·보정 방법:** ON/OFF 위치의 신호 극성 확인

#### 디지털 터치 센서

- **준비물·확인 순서:** 손가락 접촉/비접촉
- **값 해석·보정 방법:** 감지/유지 모드와 젖은 손의 영향 확인

#### 인체 감지 센서

- **준비물·확인 순서:** 사람의 정지·이동, 필요한 예열
- **값 해석·보정 방법:** 보통 움직임 감지이며 거리나 사람 수가 아님

#### 기울기 센서

- **준비물·확인 순서:** 수평·기울인 기준 자세
- **값 해석·보정 방법:** 특정 자세에서 접점 전환, 각도 °가 아님

#### 디지털 진동 센서

- **준비물·확인 순서:** 정지·가벼운 진동을 반복
- **값 해석·보정 방법:** 임계값을 넘은 감지 신호, 가속도 g 아님

#### 디지털 수위 센서

- **준비물·확인 순서:** 실제 용기와 두 수위
- **값 해석·보정 방법:** 설정 높이 통과 여부, 물의 양 L 아님

#### 포토인터럽터

- **준비물·확인 순서:** 차광판·슬롯 통과 반복
- **값 해석·보정 방법:** 막힘/열림. 속도에는 알려진 거리와 시간 측정이 추가로 필요

#### 화염 감지 센서

- **준비물·확인 순서:** 센서용 IR 시험 광원 등 통제된 시험 조건
- **값 해석·보정 방법:** 광학 감지 신호, 화염 온도나 안전 인증 경보가 아님


LCD·OLED·네오픽셀은 출력 장치이므로 센서 보정 대상이 아닙니다. 숫자가 화면에 표시된다는 사실은 측정 정확도를 확인한 것이 아닙니다. USB/BLE 송신 역시 값의 정확성을 보정하지 않습니다.

## 검증과 소스

PXT microbit 9.1.1 / pxt-core 13.0.1에서 V2 네이티브 빌드, 100개 블록 정의와 한국어 인자, 센서 프로토콜 모의 시험, 실제 바우어버드 USB/BLE 수신 함수 검사를 통과했습니다. 실물 검증 범위와 순서는 [실물검증.md](실물검증.md)에 있습니다.

`test.ts`는 전체 API 컴파일 검사 전용입니다. 여러 센서가 핀과 주소를 공유하므로 그 결과 HEX를 교실 예제로 사용하지 않습니다. [examples](examples)의 프로그램을 하나씩 사용하세요.

공급사 드라이버 출처는 [SOURCES.md](SOURCES.md), 라이선스는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 보존했습니다. 원본 소스 스냅샷·재고/가격 엑셀·내부 조사·검증 도구는 로컬 개발 폴더에 보관하며 이 공개 저장소에는 포함하지 않습니다.

아날로그 먼지의 펄스 동기 ADC 코드를 포함하며 실제 어댑터 회로·입력 전압·샘플 타이밍은 실물 검증이 남아 있습니다.
