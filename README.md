# BRIXEL Science Lab — 0.5.2 개발판

초등 디지털 과학실험을 위한 **micro:bit V2** MakeCode 확장입니다. 마빗 실드 V2와 현행 DSL 마빗 보드의 센서를 읽고 LCD·OLED·네오픽셀로 표시하거나 바우어버드 프로에 USB·BLE로 보냅니다.

## MakeCode에 추가하기

[MakeCode micro:bit](https://makecode.microbit.org/)에서 프로젝트를 열고 **확장** 검색창에 다음 주소를 붙여 넣습니다.

```text
https://github.com/brixel-editor/pxt-brixel-science-lab
```

현재 공개 버전은 `v0.5.2`입니다. 링크로 가져오는 확장이며 MakeCode의 일반 검색 목록 승인을 받은 것은 아닙니다.

설치할 때 `radio`와 호환되지 않는다는 안내가 나오면 **radio를 제거하고 brixel-science-lab을 추가**합니다. 이 확장은 BLE 통신을 사용합니다.

`v0.3.1`부터 센서 소제목을 **센서명(칩셋·모델명)**으로 통일했습니다. 예: `eCO2(SGP30)`, `CO2(MH-Z19D)`, `기압(BMP280)`. 모델이 확인되지 않은 범용 모듈에는 모델명을 붙이지 않습니다. eCO2는 CO2 환산값이며 SGP30·CCS811 블록의 선택 메뉴에서 TVOC도 읽을 수 있습니다.

생체 신호의 센서명은 **심박 센서(MAX30102)**입니다. `v0.3.5`에서 사용자가 확인한 보유 센서 칩셋에 맞춰 정정했습니다. 메이크코드가 단일 그룹 소제목을 숨기므로 블록 문구에도 같은 이름을 표시합니다. 빨간빛·적외선 맥파 원시값을 읽으며 실물 검증은 아직 하지 않았습니다.

전기 측정과 바우어버드로 보내기는 **각각 6개 블록을 기본 카테고리에 모두 표시**하며 별도의 더 보기 메뉴를 두지 않습니다. 전압의 원시값·보정·전압(V), USB·블루투스 여러 값 전송도 바로 선택할 수 있습니다.

`v0.5.1`부터 **탁도·전압 센서는 마이크로비트 아날로그 핀으로 읽습니다.** 외장 ADS1115 주소·채널 블록과 드라이버를 제거했습니다. 두 센서 모두 보정 없이 읽는 원시값(0~1023) 블록이 있고, 필요할 때 기준값으로 보정해 투과율(%)·전압(V)을 사용할 수 있습니다.

### 기존 프로젝트 업데이트

`v0.5.2`에서 지문 등록을 **`지문 번호 (1)로 [1차 등록 / 2차 등록]` 실행 블록**으로 바꿨습니다. 1차 등록 후 손가락을 떼었다가 다시 대고 2차 등록하면 센서에 저장됩니다. 각 실행 직후 `지문 상태 코드`가 0이면 성공입니다.

프로젝트마다 설치한 확장 버전이 저장됩니다. GitHub에 새 버전을 게시해도 이미 열린 프로젝트는 이전 버전을 사용할 수 있습니다.

1. 메이크코드 편집기를 새로고침합니다.
2. **JavaScript → 탐색기**를 열고 `brixel-science-lab` 옆의 **버전/새로고침 버튼**을 누릅니다.
3. 버전이 `v0.5.2`인지 확인하고 **블록** 화면으로 돌아갑니다. 생체 신호의 `지문 센서(AS608)`에서 `지문 번호 (1)로 [1차 등록]` 실행 블록을 확인합니다.

확장 검색창에 붙이는 URL의 `#v0.5.2`만으로 설치 버전이 고정되지는 않을 수 있습니다. 계속 이전 버전이라면 **탐색기 → pxt.json → Edit settings as text**에서 `dependencies` 안의 해당 항목만 다음 값으로 바꾸고 다른 파일로 이동해 저장한 뒤 편집기를 새로고침합니다.

```json
"brixel-science-lab": "github:brixel-editor/pxt-brixel-science-lab#v0.5.2"
```

기존 프로젝트의 다른 설정과 코드는 그대로 둡니다.

**이전 참·거짓 지문 등록 블록을 사용한 프로젝트:** 조건 칸에 넣었던 등록 블록은 실행 순서에 놓는 새 블록으로 교체합니다. 성공 여부를 판단하려면 등록 다음에 `지문 상태 코드 = 0` 조건을 사용합니다. TypeScript의 `enrollFingerprint(step, id)`도 이제 값을 반환하지 않습니다.

**이전 ADS1115 블록을 사용한 프로젝트:** 업데이트 전에 기존 외장 ADC 주소·탁도·전압 블록을 제거하고, 업데이트 후 새 아날로그 핀 블록을 놓아 실제 P핀을 선택합니다. A0~A3은 P0~P3과 다르므로 자동 변환하지 않습니다. TypeScript에서는 주소 설정 호출을 삭제하고 `ScienceADCChannel.A0` 등을 실제 연결의 `ScienceAnalogPin.P1` 등으로 바꿉니다. 기존 보정값은 재사용하지 않습니다.

현재 **10개 카테고리, 85개 블록**을 구현했습니다. V2 컴파일과 소프트웨어 검증을 마쳤으며, 실물 센서·보드·무선 연결 검증 전입니다. 센서별 값의 의미와 실물 검증 항목은 아래에 구분합니다.

## 시작 예제

실드 소켓의 **실제 P핀 번호**를 선택합니다. 커넥터 열 번호와 P핀 번호는 다를 수 있습니다. 모듈 전원·신호 전압을 확인합니다. 아날로그 입력은 3.3V 범위이며 P3/P4/P10을 쓰면 LED 화면이 꺼집니다.

조도 센서 P1 → USB, 0.2초마다 전송:

```typescript
basic.forever(function () {
    scienceData.sendValueUSB(scienceLight.light(ScienceAnalogPin.P1))
    basic.pause(200)
})
```

수온 센서 P8 → BLE:

```typescript
scienceData.startBluetooth()
basic.forever(function () {
    if (scienceData.bluetoothConnected()) {
        let water = scienceWater.temperature(ScienceDigitalPin.P8, 1)
        if (water != -127) scienceData.sendValueBluetooth(water)
    }
    basic.pause(1000)
})
```

바우어버드는 **구분자 쉼표**, USB는 **115200 baud**, BLE는 **micro:bit 모드**로 연결하고 기록을 시작합니다. 여러 센서는 여러 값 전송 블록의 배열에 일정한 순서로 넣습니다. 예: `scienceData.sendUSB([temperature, humidity, light])`.

한 측정은 `23.5,48,700\n` 형태입니다. 센서명·단위·진단 문구는 데이터 줄에 넣지 않습니다. 전송 블록은 반환값 없는 명령형입니다. TypeScript의 `trySendUSB`/`trySendBluetooth`는 전송 시도 여부를 반환하며 웹앱 도착 확인을 뜻하지 않습니다. 빈 배열·NaN·Infinity·연결 전 BLE 전송은 건너뜁니다.

## 값의 의미와 조건

- 단순 아날로그 센서는 0~1023 원시값입니다. lux·dB·N·UV 지수로 임의 변환하지 않습니다. 센서가 빠진 상태는 확실히 판별할 수 없습니다.
- 단순 디지털 센서는 전기 신호 0/1입니다. pH·PT100·전류 보정은 프로그램을 다시 시작하면 사라집니다.
- 온도 실패는 -127, PT100/전류/GPS는 -9999, MPU6050은 -999, 습도·거리·기압·공기질·지문 인식 등은 -1입니다. 바우어버드는 이 숫자도 표시하므로 예제처럼 해당 센서의 실패값을 검사할 수 있습니다.
- SGP30은 처음 약 15초, CCS811은 20분 동안 -1입니다. eCO₂는 환산값입니다. **MH-Z19D 블록은 직접 측정한 CO₂**이며 시작 후 60초 동안 -1입니다.
- OLED 기본은 SSD1306입니다. 실제 칩이 SH1106인 경우만 바꿉니다. 화면 크기로 칩을 단정하지 않습니다. LCD·OLED 텍스트는 영어·숫자만 지원합니다.
- 사용자가 확정한 초음파 핀 순서는 **G–V–ECHO–TRIG**입니다. 예를 들어 DSL의 G/V/P13/P14 단자라면 에코=P13, 트리거=P14를 선택합니다. 5V ECHO 신호는 전압 변환이 필요합니다.
- PMS·MH-Z19D·GPS·AS608은 V2 센서용 UART 하나를 공유합니다. **마지막에 시작한 센서 하나만 읽으며 다른 센서는 실패값**을 반환합니다(GPS -9999, 나머지 -1). USB115200 송신은 별도 UART에서 유지합니다. RX/TX는 micro:bit 기준이며 센서 TX→RX, 센서 RX→TX입니다. UART 센서 시작 블록은 시작할 때 한 번 실행합니다. GPS/AS608의 통신 속도 메뉴는 모듈 설정을 변경하지 않고 micro:bit의 속도를 맞춥니다.
- PMS는 전원 공급 후 기본 자동 송신 모드를 사용합니다. 처음 30초, 체크섬 오류, 3초 이상 수신 없음은 -1입니다. 모듈을 수동 모드로 바꿨다면 전원을 다시 켜 기본 자동 모드로 돌아온 뒤 사용합니다.
- GPS는 보유 D_031/D_032 모듈·안테나의 NMEA RMC/GGA 출력용입니다. 칩셋명은 확정하지 않았습니다. 위도·경도(소수점 도), 고도(m), 속도(km/h), 위성 수를 읽습니다. 기본 속도 9600, 각 항목은 3초 이상 갱신되지 않으면 -9999입니다. 위치 확인은 실외에서 먼저 시험합니다.
- 지문 AS608은 기본 비밀번호 0·주소 FFFFFFFF·통상 57600 baud 조건입니다. 같은 손가락을 **1차 등록 → 손가락 떼고 다시 대기 → 같은 번호로 2차 등록** 순서로 등록합니다(60초 이내). 2차 등록까지 성공하면 센서에 저장됩니다. 번호는 1부터 센서 저장 용량 미만이며 같은 번호는 덮어씁니다. 실행 직후 지문 상태 코드로 결과를 확인합니다. 인식 블록은 등록 번호를 반환하고 이미지·지문 특징 데이터는 송신하지 않습니다. 상태 0=성공, 2=손가락 없음, 9=일치 없음, 10=두 지문 불일치, -1=설정·통신·입력 오류입니다. 통신 오류 후 시작 블록을 다시 실행합니다.
- A_016/017/018 아날로그 먼지 세트는 **센서 5V 전원·VO 분압·전압에 맞는 LED 구동 회로**를 전제로 합니다. Sharp GP2Y1010 계열의 280µs 샘플/320µs LED 펄스 조건으로 직접 ADC를 읽고 8회 평균 원시값 0~1023을 반환합니다. 소제목에는 미확정 모델명을 붙이지 않습니다. PM2.5·µg/m³ 환산은 하지 않습니다. 마이크 등 ADC 스트리밍과 동시 사용하거나 펄스 타이밍을 놓치면 -1입니다. 실물 회로와 파형 검증은 남아 있습니다.
- MQ 가스 9종은 사용자 결정에 따라 MakeCode 기본 **핀 → 아날로그 값 읽기** 블록을 사용합니다. 모듈 출력이 micro:bit 입력 범위를 넘지 않도록 연결하며 원시값을 가스 농도 ppm으로 표시하지 않습니다.
- 탁도·전압은 **선택한 마이크로비트 아날로그 핀의 0~1023 원시값**을 읽습니다. 원시값 블록은 보정이 필요 없습니다. 센서 모듈의 출력 신호는 0~3.3V이면서 보드 전원 이하여야 합니다. 모듈 전원 전압과 출력 신호 전압을 구분합니다.
- 탁도 보정은 맑은 물의 원시값을 100%로 저장합니다. 작아질수록 흐린 물이며 NTU가 아닙니다. 전압은 분압 모듈을 통해 기준 계기로 확인한 직류 전압을 보정하고 같은 핀의 원시값에서 V를 계산합니다. 모듈의 25V 표기가 마이크로비트의 측정 한도를 뜻하지 않으며 실제 한도는 분압비와 핀 입력 전압에 따라 달라집니다. 측정 전압을 마이크로비트 핀에 직접 연결하지 않습니다.
- 두 센서의 보정은 핀별로 저장되고 재시작하면 사라집니다. 보정 기준 원시값은 5~1022여야 합니다. 잘못된 재보정은 해당 핀의 이전 보정을 지웁니다. 보정 전·입력 포화(1023)는 보정값 블록에서 -1을 반환하며 원시값 블록에서는 1023을 그대로 볼 수 있습니다. 아날로그 센서 미연결은 확실히 식별할 수 없습니다.
- MAX30102는 20~100ms마다 읽는 광학 원시값이며 심박수·SpO₂가 아닙니다. EC11은 손으로 천천히 돌리는 신호 주기 수이며 빠른 회전은 놓칠 수 있습니다. APDS9960 방향은 0 없음/1 위/2 아래/3 왼쪽/4 오른쪽이고 한 번 읽으면 지워집니다.
- DS1307은 이미 설정되어 동작 중인 시계의 시·분·초를 읽습니다. MPU6050(0x68), TCS34725/VL53L0X(0x29), MLX90614/CCS811(0x5A)은 같은 주소끼리 직접 병렬 연결하지 않습니다.

## 검증과 소스

PXT microbit 9.1.1 / pxt-core 13.0.1에서 V2 네이티브 빌드, 85개 블록 정의와 한국어 인자, 센서 프로토콜 모의 시험, 실제 바우어버드 USB/BLE 수신 함수 검사를 통과했습니다. 실물 검증 범위와 순서는 [실물검증.md](실물검증.md)에 있습니다.

`test.ts`는 전체 API 컴파일 검사 전용입니다. 여러 센서가 핀과 주소를 공유하므로 그 결과 HEX를 교실 예제로 사용하지 않습니다. [examples](examples)의 프로그램을 하나씩 사용하세요.

공급사 드라이버 출처는 [SOURCES.md](SOURCES.md), 라이선스는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 보존했습니다. 원본 소스 스냅샷·재고/가격 엑셀·내부 조사·검증 도구는 로컬 개발 폴더에 보관하며 이 공개 저장소에는 포함하지 않습니다.

아날로그 먼지의 펄스 동기 ADC 코드를 포함하며 실제 어댑터 회로·입력 전압·샘플 타이밍은 실물 검증이 남아 있습니다.
